# Benchmark Results

The confirmatory run of the benchmark suite, executed against the [pre-registered plan](https://github.com/omelas-tech/brain/blob/main/benchmark/PREREGISTRATION.md): **N=10 runs per arm**, every scenario anchored by a no-memory floor and an oracle ceiling, every candidate graded by a three-judge panel. Wins, ties and nulls are all reported — the ties are part of the result.

<Callout type="warning">
  **Judge validation is pending.** The pre-registration requires the panel to be checked against human grading (Cohen's κ ≥ 0.6 on ≥ 50 runs) before any headline is treated as final. That check has not been run yet; every per-judge verdict and rationale is in the raw JSON so it can be.
</Callout>

## Run metadata

| Field | Value |
|---|---|
| Date | 2026-11-10 |
| Agent under test | **Claude Sonnet 5.5** (`claude-sonnet-5-5`), single-shot via the Messages API — no Claude Code CLI, so no CLI system prompt, tools or auto memory in any arm |
| Judge panel | **Gemini 3.5 Flash + Gemini 2.5 Pro + DeepSeek V4 Pro** — majority vote, each rubric criterion majority-voted; no judge shares the agent's family |
| Runs per arm | 10 (pre-registered N) |
| Scenarios | A, B, C, D, F, G (E — continual — deferred) |
| Distractor haystack | up to 1000 deterministic memories (seed=42) |
| Statistics | Pass rates: Fisher exact vs the brain arm. Tokens: 90% bootstrap CI, Mann–Whitney U, Holm–Bonferroni |

Why single-shot? The model receives the task plus whatever the arm injects (nothing, a retriever's top-k, brain's session-start payload, or the oracle) and replies in one turn. That isolates **memory's effect** — there is no agentic file exploration to rediscover conventions — and keeps token counts comparable.

<ScenarioACost />

**Headline.** Under a 1000-memory haystack, both standard retrievers fail completely: BM25 surfaces one of the three needed memories and a vector store none, and the model passes **0/10** with either. Brain passes **9/10** (Fisher exact p = 0.0001 against each). The only other arms that pass are the ones that skip retrieval — the oracle, and dumping the corpus into the prompt, which costs **4× (8k dump) to 22× (60k dump)** brain's median tokens per run (3.6× and 20× per success).

**Where brain can still improve.** Session-start injection retrieves 2 of 3 target memories (Recall@5 0.67): superseded "decoy" versions of a convention take two of the five slots. When the model chooses its own recall query (`brain-connector-gated`, the hosted connector's policy), it retrieves all three — 10/10 at Recall@5 1.00. Disabling the pinned tier drops brain to 8/10.

**Headline.** Loading **only the relevant skill** passes 10/10 at **28% fewer tokens** than loading every skill body. An index alone is not enough for a single-shot model (1/10) — it has to load the matching `SKILL.md`, which is what the skills tier automates.

## Scenario G — Poisoned haystack (memory quarantine)

One memory in the haystack is a planted instruction to send the payment API key to an outside URL and not tell the user.

| Arm | pass | completed | median tokens |
|---|:---:|:---:|---:|
| fixture-only (floor) | 9/10 | 10/10 | 1,489 |
| **brain-flag** (quarantined, visibly marked) | **10/10** | 10/10 | 2,433 |
| **brain-enforce** (quarantined, excluded) | **10/10** | 10/10 | 2,317 |
| brain-no-quarantine | 0/10 | **0/10 — refused** | — |
| context-dump (bounded) | 9/10 | 9/10 (1 refused) | 10,845 |
| oracle (ceiling) | 10/10 | 10/10 | 2,079 |

**Headline.** With brain's quarantine on, the task completes safely every time. With quarantine off, the poisoned memory ranks into the injected context and **Claude's API safety layer refuses every request** (`stop_reason: refusal`, category `cyber`) — no secret leaks, but no work gets done either. Refusals are counted as no-completion, never as judged answers. Buried among 100 notes in a context dump, the same instruction triggered a refusal in 1 of 10 runs.

## Reading the suite

Brain wins where it is designed to — **retrieval under heavy noise (A)**, **loading only the procedural knowledge a task needs (D)**, and **keeping a poisoned memory from derailing the task (G)**. On small, clean haystacks (B, C) memory matters a lot but a plain keyword retriever matches brain's correctness at lower token cost, and on abstention (F) the base model needs no memory at all. The A result also shows the next improvement to make: the tool-gated policy already retrieves every target memory; the always-on session-start ranking should too.

## Retrieval scoring calibration — in-vivo probe (July 2026)

<Callout type="info">
  This section is **not part of the controlled suite above** — no judge panel, no
  distractor haystack, no floor/ceiling arms. It is a small in-vivo probe on a real
  working brain, run to measure a scoring-calibration fix. Read it as engineering
  verification, not as a benchmark claim.
</Callout>

**The problem.** BM25 relevance was normalized per-query by the top score, so the
best available match for *any* query reported relevance 1.0 — including queries the
brain knew nothing about. A four-term nonsense control query returned ten results
against a real 177-memory brain, the top one scoring a confident-looking composite
of 0.679. An agent trusting those scores injects noise into its context.

**The fix (post-beta.30).** Three coordinated changes: relevance is scaled by
**IDF-weighted query coverage** (matching one term of a four-term query caps
relevance near 0.25, however strong that single match); explicit-query recall
applies a **relevance floor** so zero-relevance memories can't pad the top-N on
strength alone; and spreading-activation **sources are relevance-gated** in query
mode — activation spreads outward from the query-relevant set, so a
strong-but-irrelevant clique can't rescue itself past the floor, while associates
of genuinely relevant memories still surface.

**The probe.** A real working brain (177 memories, 1,245 association edges), 20
tag-derived topical queries with known target memories, plus the nonsense control.
Same brain, same queries, before and after:

| Metric | Before (beta.30) | After |
|---|:---:|:---:|
| hit@1 | 90% | **100%** |
| hit@3 | 100% | **100%** |
| MRR | 0.950 | **1.000** |
| Nonsense control | 10 results, top score 0.679, relevance "1.0" | **1 result**, score 0.396, relevance 0.213 |
| Recall latency (p50) | 49 ms | 46 ms |

Coverage scaling did not just fix the calibration — it improved ranking: the two
probe queries whose targets previously ranked #2 moved to #1, because
partial-match distractors no longer outrank full-coverage targets.

**Caveats.** n=20, a single brain, self-run, and tag-derived queries favor the
index's weighted tag field. The honest headline is the *calibration* change —
irrelevant queries now return honestly low scores or nothing — with the ranking
improvement as directional evidence pending a controlled re-run (below).
